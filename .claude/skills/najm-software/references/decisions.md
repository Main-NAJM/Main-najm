## 1. المنظومة التقنية

المستودع محسوم. لا تقترح تغييره ولا تسأل عنه.

| الطبقة | القرار |
| --- | --- |
| الواجهة | React 18 + TypeScript (`strict`) |
| البناء | Vite 6 |
| التوجيه | React Router 6 |
| الخلفية | Firebase (Firestore + Auth) |
| الاستضافة | Firebase Hosting |
| الأنماط | CSS عادي + متغيّرات في `src/styles/global.css` |
| اللغة | عربية، `lang="ar" dir="rtl"` |
| الخط | Tajawal (أوزان 400 · 500 · 700 · 800 — لا وزن 600) |

**لا تُدخل:** Tailwind، styled-components، Redux، MUI، Bootstrap، أو أي إطار CSS.
النظام القائم كافٍ ومتّسق — إدخال ثانٍ يُنتج واجهتين في تطبيق واحد.

**TypeScript:** `strict` مفعّل. لا `any` — استخدم `unknown` مع تضييق، أو عرّف النوع.
لا `@ts-ignore` بلا سطر تعليق يشرح السبب.

## 2. بنية الملفات

اتبع القائم في `src/`:

```
src/
  components/   مكوّنات مشتركة قابلة لإعادة الاستعمال
  pages/        شاشة لكل ملف
  hooks/        منطق قابل لإعادة الاستعمال (use…)
  context/      حالة عامة
  lib/          مساعدات، عملاء Firebase، أدوات
  data/         ثوابت، أنواع، بذور
  styles/       global.css — مصدر الرموز الوحيد
  print/        قوالب الطباعة
```

**القواعد:**
- ملف واحد لكل مكوّن، والاسم `PascalCase.tsx` مطابق لاسم المكوّن.
- المكوّن الذي يتجاوز ~250 سطرًا يُقسَّم. المنطق يخرج إلى `hooks/`.
- المكوّن المستخدَم في مكان واحد يبقى بجوار مستخدمه؛ لا تُرقّه إلى `components/`
  قبل أن يُستخدم مرّتين فعلًا.
- الأنواع المشتركة في `data/types.ts`؛ الأنواع المحلية أعلى ملفها.

## 3. الأنماط والتصميم

- **الرموز مصدر واحد.** كل لون ومسافة ونصف قطر وظلّ من `src/styles/global.css`.
  قيمة جديدة ⇒ أضف رمزًا هناك أولًا، لا قيمة خامّة في المكوّن.
- **CSS في ملف مرافق** (`Component.css` بجوار `Component.tsx`) أو في `global.css`
  للأنماط المشتركة. الأنماط السطرية (`style={{}}`) للقيم المحسوبة وقت التشغيل فقط.
- **أسماء الأصناف بادئة بالمكوّن:** `.order-card__title` لا `.title`.
- **لا `!important`** إلا لتجاوز نمط مكتبة خارجية، مع تعليق.
- **الخصائص المنطقية إلزامية** (راجع `responsive.md` §7).

## 4. الحالة والبيانات

**تدرّج الاختيار — من الأبسط:**
1. `useState` محلي — الافتراض الأول دائمًا.
2. رفعها للأب المشترك — إن احتاجها أخوان.
3. `Context` — إن عبرت ثلاث طبقات أو أكثر، أو كانت عامة فعلًا (مستخدم، إعدادات، لغة).
4. لا شيء أبعد. لا مكتبة إدارة حالة.

**Firestore:**
- الاشتراك الحيّ (`onSnapshot`) للبيانات المعروضة؛ القراءة المفردة (`getDoc`) للمرّة الواحدة.
- **ألغِ كل اشتراك** في تنظيف `useEffect`. التسريب هنا يُنتج قراءات تُحاسَب عليها فواتير.
- الكتابة **متفائلة** (اعرض فورًا، تراجَع عند الفشل).
- استخدم `serverTimestamp()` للطوابع الزمنية لا `Date.now()` — ساعة الجهاز غير موثوقة.
- كل استعلام له `limit()`. ولا تجلب مجموعة كاملة لتصفّيها في المتصفح.
- قواعد الأمان في `firestore.rules` تُحدَّث مع كل مجموعة جديدة. لا تترك مجموعة مفتوحة.

**الوقت والمال:**
- المبالغ **أعدادًا صحيحة بأصغر وحدة** (قروش/سنتات) لا `float`. حسابات النقود بالعشرية
  العائمة تُنتج فروقًا تُفقد الثقة.
- التواريخ `Timestamp` من Firestore، وتُعرَض بـ `Intl.DateTimeFormat('ar', …)`.

## 5. النماذج والتحقّق

- **بلا مكتبة.** `useState` + دالة تحقّق. النماذج هنا بسيطة ولا تستحقّ اعتمادًا.
- **التحقّق عند `blur`** لا عند كل ضغطة مفتاح — التصحيح أثناء الكتابة مزعج.
  وبعد أول خطأ، حدّث حيًّا كي يرى المستخدم تصحيحه.
- **رسالة الخطأ تحت الحقل**، بالعربية، وتقول ما المطلوب: «أدخل رقم هاتف من 10 أرقام»
  لا «قيمة غير صالحة».
- **زر الإرسال لا يُعطَّل** قبل المحاولة — التعطيل يُخفي سبب المنع. اتركه فعّالًا،
  وعند الضغط أظهر الأخطاء وانقل التركيز لأول حقل خاطئ.
- **منع الإرسال المزدوج:** عطّل الزر *أثناء* الإرسال فقط، مع مؤشّر تحميل داخله.
- **`inputMode` و`autoComplete` صحيحان** — `inputMode="numeric"` للأرقام يفتح لوحة
  المفاتيح الرقمية على الجوال؛ إغفاله عيب ملموس.

## 6. التعامل مع الأخطاء

- **لا خطأ صامت.** كل `catch` إمّا يعرض للمستخدم أو يسجّل عمدًا بتعليق يشرح الصمت.
- **لا تسريب تقني للواجهة.** حوّل الخطأ إلى جملة عربية مفيدة. سجّل الأصل في
  `console.error` للتشخيص.
- **`ErrorBoundary` حول كل صفحة** — انهيار مكوّن لا يُفرغ الشاشة كلها.
- **تصنيف الأخطاء:** اتصال («تحقّق من الاتصال ثم أعد المحاولة») مقابل صلاحية
  («ليس لديك إذن») مقابل تحقّق (اعرضه عند الحقل) مقابل غير متوقّع («حدث خطأ —
  أعد المحاولة» + زر).

## 7. الأداء

- **الأولوية للمحسوس** لا للأرقام: استجابة اللمسة، غياب قفزات التخطيط، سلاسة التمرير.
- **`React.lazy` + `Suspense`** لكل صفحة في الموجّه — يقلّل الحزمة الأولى.
- **لا تحسين سابق لأوانه.** `useMemo`/`useCallback`/`memo` تُضاف عند وجود بطء مقيس،
  لا استباقًا — لها كلفة ذهنية وكلفة ذاكرة.
- **القوائم الطويلة (>100 عنصر):** ترقيم أو تحميل تدريجي. الافتراضية (virtualization)
  فوق 500.
- **`key` ثابت وفريد** في القوائم — لا `index` إن كان الترتيب يتغيّر.
- **الميزانية:** حزمة أولى < 200KB مضغوطة، وتفاعل أول < 2.5 ثانية على شبكة 3G سريعة.

## 8. التسمية والصياغة

| العنصر | القاعدة | مثال |
| --- | --- | --- |
| المكوّنات | `PascalCase` إنجليزي | `OrderCard` |
| الدوال والمتغيّرات | `camelCase` إنجليزي | `formatAmount` |
| الثوابت | `SCREAMING_SNAKE` | `MAX_ITEMS` |
| الملفات | مطابق لما يُصدّره | `OrderCard.tsx` |
| أصناف CSS | `kebab-case` ببادئة | `.order-card__title` |
| حقول Firestore | `camelCase` إنجليزي | `createdAt` |
| **واجهة المستخدم** | **عربية دائمًا** | «إضافة طلبية» |

الكود بالإنجليزية والواجهة بالعربية. لا تخلط: لا متغيّر بالعربية، ولا نص إنجليزي يظهر للمستخدم.

**المفهوم الواحد اسم واحد** في التطبيق كلّه — في الكود وفي الواجهة. راجع الموجود قبل أن تسمّي.

## 9. المكتبات الخارجية

الافتراض: **لا**. قبل إضافة أي اعتماد، اسأل نفسك بالترتيب:

1. هل يحلّها المتصفح أصلًا؟ (`Intl`، `fetch`، `crypto.randomUUID`، `Date`،
   `structuredClone`، `URLSearchParams`، `IntersectionObserver`)
2. هل تُكتب في أقل من ~60 سطرًا؟ اكتبها في `lib/`.
3. هل الحزمة صغيرة ومصانة وبلا اعتمادات متشعّبة؟

أضفها فقط إن مرّت الثلاثة، واذكرها في تقرير التسليم بسطر واحد.
**مرفوضة مسبقًا:** moment، lodash، jQuery، أي إطار CSS، أي مكتبة إدارة حالة.

## 10. متى تسأل فعلًا

بطاقة القرار (نعم/لا) مسموحة فقط في هذه الحالات:

- **فعل غير قابل للتراجع:** حذف بيانات إنتاج، نشر للعموم، تغيير قواعد أمان تفتح وصولًا،
  إرسال إشعارات/رسائل لمستخدمين حقيقيين، تغيير سعر أو فاتورة.
- **تغيير سلوك يراه المستخدم الحالي ويعتمد عليه:** نقل ميزة، تغيير معنى حقل، إزالة شاشة.
- **تفرّع منتجي حقيقي:** طريقان مختلفان في *ما يفعله* المنتج لا في *كيف* يُبنى.
- **تعارض مع طلب سابق صريح** من ناجم.

وما عدا ذلك — **احسم ونفّذ**، واذكر قرارك في قسم «قرارات اتخذتها نيابةً عنك».

أمثلة على ما **لا** يُسأل عنه إطلاقًا: أي مكتبة، أي بنية ملفات، أي اسم متغيّر أو ملف،
أي لون أو مسافة أو خط، أي شكل بيانات، أي نقطة انكسار، أي طريقة تخزين، أي صيغة API،
أي خوارزمية، أي قرار أداء، أي نمط كود.

## 11. الأسرار والأمان

**سرّان مختلفان لا يُخلطان:**

| النوع | مثاله | أين يعيش |
| --- | --- | --- |
| **إعداد عميل عامّ** | `VITE_FIREBASE_*` الستة | `.env.production` — يُرفع مع الكود. يُشحن في كل حزمة على أي حال، والحماية من `firestore.rules` لا من إخفائه |
| **سرّ حقيقي** | مفتاح Admin SDK / حساب الخدمة، رمز API خاصّ، كلمة مرور | **لا يدخل المستودع ولا المحادثة إطلاقًا.** مكانه الوحيد: GitHub → Settings → Secrets → Actions → Repository secret |

**قواعد ثابتة:**
- لا تطلب من ناجم لصق مفتاح خاصّ في المحادثة، وإن بدأ فأوقفه ووجّهه إلى مكانه الصحيح.
- `.env.local` في `.gitignore` — فما يُوضع فيه لا يصل إلى نسخة النشر. إن احتاجه البناء
  فمكانه `.env.production` (عامّ) أو سرّ في الإجراءات (خاصّ).
- كل مجموعة Firestore جديدة تُغلق بقاعدة في `firestore.rules` قبل التسليم، وتُغطّى
  باختبار في `scripts/test-rules.mjs`.
- لا تسجّل بيانات شخصية (هاتف، بريد، مبلغ عميل) في `console` في نسخة الإنتاج.

## 12. التعليقات

بالعربية، قصيرة، وتشرح **لماذا** لا **ماذا**.

```ts
// ✗ بلا فائدة — الكود يقول هذا بنفسه
// نضرب الطول في العرض
const area = l * w;

// ✓ يشرح قرارًا لن يُستنتج من الكود
// الفتحة ليست إطارًا حول محيطها: نافذة ١×١ فيها ١١ قطعة بروفيل لا أربع،
// فالحساب بالمحيط يضعها عند أقلّ من نصف ثمنها.
const profileMetres = pieces * pieceLength;
```

علّق حيث يسأل القارئ «لماذا هكذا؟»: رقم سحري له سبب، التفاف حول عيب متصفّح، قرار أداء،
قاعدة عمل جاءت من ناجم. وما عدا ذلك — اسمٌ جيّد أنفع من تعليق.
