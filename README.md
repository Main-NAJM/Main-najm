# حرفة برو (Herfah Pro)

تطبيق ويب تقدّمي (PWA) لتنظيم عمل **الحرفيين والتجار**: الطلبيات، المواعيد، حساب التكلفة
والربح، مؤشرات أسعار السوق، سجل الديون، وطباعة الفواتير والكشوف.

يعمل على الهاتف والحاسوب من نفس الشيفرة، ويمكن تثبيته كتطبيق مستقل على الجهاز، ويعمل دون
اتصال بالإنترنت.

## التقنيات

- **React 18 + TypeScript + Vite** — المسار الاقتصادي: قاعدة شيفرة واحدة للويب والموبايل.
- **PWA** — ملف `manifest.webmanifest` وعامل خدمة (`public/sw.js`) للعمل دون إنترنت، ودعوة
  تثبيت تظهر في أعلى الصفحات متى سمح المتصفّح، تُغلق مرّة فلا تُلحّ، ويبقى الزر في الإعدادات.
- **حسابات على الجهاز** — بلا خادم: الحساب في `localStorage` وكلمة المرور مُلبّدة بـ
  PBKDF2‑SHA256 (‎150 ألف دورة، ملح عشوائي لكل حساب). تكفي لفصل الحسابات على الجهاز الواحد
  وحمايتها من الفضولي، وليست بديلاً عن مصادقة خادم لمن يملك الجهاز وخبرة تقنية.
- **Firebase (اختياري)** — المصادقة (Auth) بثلاث طرق: البريد وكلمة المرور، وحساب Google،
  ورقم الهاتف برمز تحقّق؛ وقاعدة البيانات (Firestore) مع تخزين محلي دائم للمزامنة بعد
  انقطاع الاتصال. تظهر هذه الطرق في شاشة الدخول متى وُجدت مفاتيح Firebase.
- **بدون مكتبات واجهة خارجية** — تنسيق RTL مكتوب يدوياً، يدعم الوضع الليلي تلقائياً.

## التشغيل محلياً

```bash
npm install
npm run dev
```

يفتح التطبيق على `http://localhost:5173` على شاشة إنشاء حساب. الحساب يُحفظ على الجهاز،
وبياناته معه، بلا حاجة إلى Firebase.

عند إنشاء الحساب تُختار المهنة، فيبني عليها التطبيق بدايته: قوالب تسعير حرفتها، وأسعار
مادّتها في مؤشّر السوق، ونسبة ربح وأجرة ساعة مبدئيتين، وتسمية المهنة في رأس كل صفحة.

ومن لا يجد مهنته في القائمة يكتبها بنفسه: اسمها، ومادّته الأساسية، وطريقة تسعيره
المعتادة. فيحمل التطبيق اسمه هو — في رأس الصفحات وفي قوالب التسعير وفي عروض الأسعار
المطبوعة — ويصير لمادّته صنفها الخاصّ في مؤشّر الأسعار، ويبدأ بقالب تسعير بأساس تسعيره.
لا تُزرع طلبيات ولا ديون تجريبية لحساب حقيقي — البيانات التجريبية الكاملة بضغطة زر صريحة
من الإعدادات.

> **حساب واحد على الجهاز من قبل؟** أوّل حساب يُنشأ يرث بيانات المستخدم المحلي السابق،
> فلا يضيع شيء ممّن كان يستعمل التطبيق قبل وجود الحسابات.

أوامر أخرى:

```bash
npm run build     # بناء نسخة الإنتاج في مجلد dist
npm run preview   # معاينة نسخة الإنتاج
npm run lint      # فحص الأنواع بـ TypeScript
```

## الموقع التعريفي (مؤسسة الباشة للمعادن)

مجلد `site/` يحوي موقعاً تعريفياً من صفحة واحدة، مستقلاً عن تطبيق حرفة برو. لتشغيله محلياً:

```bash
npm run site        # ثم افتح http://localhost:8080
npm run site -- 3000  # منفذ مخصّص
```

يطبع الأمر أيضاً رابط الشبكة المحلية (`http://192.168.x.x:8080`) لفتح الموقع من الهاتف على
نفس شبكة الواي‑فاي.

وعلى الإنترنت يُنشر الموقع مع التطبيق في نفس مشروع Firebase على المسار `/albacha`:

```bash
npm run deploy -- --project <اسم-مشروعك-على-Firebase>
```

| العنوان | المحتوى |
| --- | --- |
| `https://<اسم-المشروع>.web.app/` | تطبيق حرفة برو |
| `https://<اسم-المشروع>.web.app/albacha` | موقع مؤسسة الباشة للمعادن |
| `https://<اسم-المشروع>.web.app/app` | تطبيق إدارة زبائن الباشة |
| `https://<اسم-المشروع>.web.app/om-aya` | متجر أم آية |

الموقع مُهيّأ أيضاً كتطبيق ويب تقدّمي (PWA) بأيقونته الخاصة، فيمكن تثبيته على الشاشة
الرئيسية والعمل به دون إنترنت بعد النشر على https.

التفاصيل والتثبيت كتطبيق والنشر التلقائي عبر GitHub Actions في [`site/README.md`](site/README.md).

## محاكي Firebase — تجربة المزامنة بلا مشروع سحابي

قبل ربط مشروع حقيقي، يمكن تشغيل **Auth و Firestore حقيقيَّين على جهازك**: لا حساب
Google، ولا مفاتيح، ولا فاتورة. هذا ما يسمح باختبار المزامنة بين الأجهزة والعمل دون
اتصال وقواعد الأمان — وهي أمور لا يغطّيها «الوضع المحلي» لأنه لا يمرّ بخادم أصلًا.

يحتاج **Java** (موجودة مع أغلب الأنظمة؛ للتحقّق: `java -version`).

```bash
npm run emulators       # نافذة أولى — Auth على 9099 و Firestore على 8080
npm run dev:emulator    # نافذة ثانية — حرفة برو موصولًا بهما
npm run app:emulator    # أو تطبيق الباشة
```

واجهة المحاكي على `http://127.0.0.1:4000` تعرض المستخدمين والبيانات مباشرة.

أنشئ حسابًا بالبريد وكلمة المرور من شاشة الدخول كالمعتاد — يُنشأ داخل المحاكي.
افتح التطبيق في نافذتَي متصفّح مختلفتين بالحساب نفسه لترى المزامنة الحيّة بينهما.
في الإعدادات يظهر «التخزين: محاكي Firebase (على هذا الجهاز)» كي لا يختلط الأمر.

> بيانات المحاكي **مؤقّتة**: تختفي عند إيقافه. هذا مقصود.

الإعدادات في `.env.emulator` (مرفوع إلى Git لأنه لا يحوي أي سرّ — المحاكي لا يتحقّق
من المفاتيح). ولا يُحمَّل إلا مع `--mode emulator`، فلا يتسرّب أبدًا إلى بناء الإنتاج.

### اختبار قواعد الأمان

```bash
npm run emulators       # نافذة أولى
npm run test:rules      # نافذة ثانية
```

يشغّل ٢٠ فحصًا على `firestore.rules`: صاحب البيانات يقرأ ويكتب، ومستخدم آخر لا يقرأ
ولا يكتب، وزائر بلا تسجيل دخول ممنوع، والمجموعات خارج القائمة المسموحة مرفوضة. ومتجر أم
آية هو الاستثناء المقصود، فله فحوصه: الزائر يقرأ المنتجات والإعدادات بلا حساب، ولا يكتبها
هو ولا مستخدم مسجَّل ليس صاحبة المتجر.

شغّله بعد أي تعديل على `firestore.rules` وقبل `deploy --only firestore:rules`. القواعد
هي الشيء الوحيد الذي يفصل بيانات زبون عن زبون، وخطأ حرف واحد فيها لا يظهر في أي
شاشة ولا في أي بناء — يظهر يوم يقرأ أحدهم بيانات غيره.

ولا حاجة لتذكّره: **سير عمل النشر يشغّله تلقائيًا قبل كل نشر**، فلا تصل قاعدة ذات
ثغرة إلى الإنتاج. وإن فشل فحص واحد، يتوقّف النشر ويُسمّي الفحص الذي سقط.

بلا محاكي يدوي، بنفس ما يفعله سير العمل:

```bash
npx firebase-tools@13 emulators:exec --only firestore "npm run test:rules"
```

## ربط Firebase

المشروع المستعمل مضبوط في `.firebaserc`: **`albacha-metals-fecd8`**.

### ١. تسجيل تطبيق الويب وكتابة المفاتيح — بأمر واحد

```bash
npx firebase-tools@13 login   # مرّة واحدة على الجهاز
npm run firebase:setup
```

السكربت يقرأ المشروع من `.firebaserc`، ويبحث عن تطبيق ويب في المشروع فيُنشئ واحداً إن لم
يوجد، ثم يجلب إعدادات SDK ويكتبها في `.env.local`. لاستبدال ملف موجود: `npm run firebase:setup -- --force`،
ولمشروع آخر: `npm run firebase:setup -- --project <id>`.

<details>
<summary>الطريقة اليدوية بدل السكربت</summary>

من **Project settings → Your apps → Web** أضف تطبيقاً، ثم انسخ `.env.example` إلى
`.env.local` واملأ `VITE_FIREBASE_*` من إعدادات SDK.

</details>

### ٢. تفعيل طرق الدخول (من الكونسول، مرّة واحدة)

**Authentication → Sign-in method** ← فعّل الثلاثة:

| الطريقة | ما تحتاجه |
| --- | --- |
| **Email/Password** | التفعيل فقط |
| **Google** | التفعيل + اختيار بريد دعم المشروع |
| **Phone** | التفعيل + خطة **Blaze** (الرسائل مدفوعة). للتجربة بلا رسائل: أضف رقماً تجريبياً ورمزه من **Phone numbers for testing** |

ثم من **Authentication → Settings → Authorized domains** أضف النطاق الذي ستفتح منه
التطبيق (`localhost` مضاف تلقائياً، و`albacha-metals-fecd8.web.app` يُضاف عند النشر).

### ٣. قاعدة البيانات

أنشئ **Firestore Database** ثم انشر قواعد الأمان:

```bash
npx firebase-tools@13 deploy --only firestore:rules
```

بمجرّد وجود القيم في `.env.local` تظهر شاشة تسجيل الدخول بطرقها الثلاث وتبدأ المزامنة بين
الأجهزة. كل مستخدم يرى بياناته وحده — القواعد تمنع أي وصول متبادل.

> ملف `.env.local` مستبعد من Git، فلا تُرفع مفاتيحك إلى المستودع.

### بنية البيانات في Firestore

```
users/{uid}                      ← وثيقة المستخدم، تحتوي حقل profile
users/{uid}/orders/{id}          ← الطلبيات
users/{uid}/appointments/{id}    ← المواعيد
users/{uid}/calculations/{id}    ← سجل حسابات التكلفة
users/{uid}/marketPrices/{id}    ← أسعار المواد
users/{uid}/debts/{id}           ← سجل الديون

shop/omAya/products/{id}         ← منتجات متجر أم آية
```

قواعد الأمان تمنع أي مستخدم من قراءة أو كتابة بيانات مستخدم آخر.

أما منتجات متجر أم آية فخارج `users/` عمداً: **يقرأها الجميع** بلا تسجيل دخول لأن المتجر
واجهة عامّة، **ولا يكتبها إلا الحساب المذكور في `firestore.rules`** — وهو ما يُضبط مرّة
واحدة بمعرّف حساب صاحبة المتجر. التفصيل في [`om-aya/README.md`](om-aya/README.md).

## النشر

### Firebase Hosting — تلقائياً من GitHub (موصى به)

المستودع يحتوي على سير عمل جاهز في `.github/workflows/deploy-firebase.yml` يبني التطبيق
وينشره على Firebase Hosting مع كل دفعة إلى `main`، وينشر معه قواعد أمان Firestore.

**الإعداد لمرة واحدة.** أضف سرّين من **Settings → Secrets and variables → Actions →
New repository secret**:

| اسم السرّ | من أين تأتي قيمته |
| --- | --- |
| `FIREBASE_PROJECT_ID` | كونسول Firebase → Project settings → General → حقل **Project ID** |
| `FIREBASE_SERVICE_ACCOUNT` | كونسول Firebase → Project settings → **Service accounts** → **Generate new private key** → افتح الملف المنزَّل والصق محتواه كاملاً |

بعدها يعمل النشر تلقائياً عند أول دفعة إلى `main`، أو يدوياً من تبويب **Actions** عبر
**Run workflow**. الرابط الناتج شكله:

```
https://<project-id>.web.app
```

**مفاتيح التطبيق (اختيارية).** لتفعيل تسجيل الدخول والمزامنة بين الأجهزة أضف أيضاً أسرار
`VITE_FIREBASE_*` بنفس أسماء `.env.example`. بدونها يُنشر التطبيق ويعمل بالتخزين المحلي على
جهاز كل مستخدم.

> سير العمل يتوقّف برسالة واضحة إن كان أحد السرّين ناقصاً، بدل أن يفشل في منتصف النشر.
> ومفتاح حساب الخدمة يُكتب إلى ملف مؤقّت ولا يُطبع في السجلّات إطلاقاً.

### Firebase Hosting — يدوياً من جهازك

```bash
npm run build
npx firebase-tools login
npx firebase-tools use --add          # اختر مشروعك
npx firebase-tools deploy --only hosting
```

ملف `firebase.json` جاهز: ينشر مجلّد `dist`، ويوجّه كل المسارات إلى `index.html` (توجيه من
طرف العميل)، ويمنع تخزين `sw.js` مؤقتاً حتى تصل التحديثات للمستخدمين.

> انتبه إلى `--only hosting`. بدونها قد يدخل Firebase في مسار **App Hosting**، وهو منتج
> مختلف مخصّص للتطبيقات التي تُصيَّر على الخادم. هذا التطبيق موقع ثابت ولا يحتاجه.

### أي استضافة ثابتة أخرى

ارفع محتويات مجلد `dist` مع إعادة توجيه كل المسارات إلى `index.html`.

## التثبيت على الهاتف

بعد فتح الموقع على الهاتف:

- **أندرويد (Chrome)**: القائمة ← «تثبيت التطبيق»، أو زر التثبيت داخل صفحة الإعدادات.
- **آيفون (Safari)**: زر المشاركة ← «إضافة إلى الشاشة الرئيسية».

يعمل التطبيق بعدها كتطبيق مستقل بملء الشاشة، ويشتغل دون إنترنت.

للحصول على تطبيق متجر حقيقي لاحقاً يمكن تغليف نفس الشيفرة عبر
[Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) أو Capacitor دون إعادة كتابة
الواجهة.

## بنية المشروع

```
src/
  components/     مكوّنات الواجهة المشتركة (حقول، نوافذ، بطاقات، أيقونات، الهيكل العام)
  context/        حالة المصادقة والبيانات والتنبيهات
  data/           طبقة التخزين: Firestore أو التخزين المحلي خلف واجهة واحدة
  hooks/          خطّافات مساعدة (تثبيت PWA)
  lib/            الأنواع، الحسابات، التنسيق، الثوابت، إعداد Firebase
  pages/          الشاشات: لوحة اليوم، الطلبيات، المواعيد، الحاسبة، الأسعار، الديون، الطباعة، الإعدادات
  print/          توليد مستندات الطباعة بتنسيق A4
  styles/         التنسيق العام (RTL + وضع ليلي)
public/           أيقونات التطبيق، ملف الـ manifest، عامل الخدمة
```

طبقة التخزين موحّدة خلف الواجهة `Store` في `src/data/store.ts`، لذا يعمل التطبيق بنفس
الشيفرة سواء كانت البيانات في Firestore أو في المتصفّح.

## النسخ الاحتياطي

من **الإعدادات ← النسخ الاحتياطي** يمكن تصدير كل البيانات كملف JSON واستعادتها لاحقاً على
جهاز آخر. يُنصح بذلك بشكل دوري عند العمل في الوضع المحلي.
