# حرفة برو (Herfah Pro)

تطبيق ويب تقدّمي (PWA) لتنظيم عمل **الحرفيين والتجار**: الطلبيات، المواعيد، حساب التكلفة
والربح، مؤشرات أسعار السوق، سجل الديون، وطباعة الفواتير والكشوف.

يعمل على الهاتف والحاسوب من نفس الشيفرة، ويمكن تثبيته كتطبيق مستقل على الجهاز، ويعمل دون
اتصال بالإنترنت.

---

## الميزات

| القسم | الوظائف |
| --- | --- |
| **الطلبيات** | إضافة وتعديل وحذف، حالات (جاري / معلّق / مكتمل)، بنود بالكمية والسعر، أجور وخصم ومدفوعات، بحث وتصفية، طباعة فاتورة |
| **تنظيم الوقت** | مواعيد يومية بالوقت والمدة، ربط الموعد بطلبية، تجميع حسب اليوم، تعليم الإنجاز |
| **حاسبة التكلفة والربح** | مواد + نسبة هالك + ساعات عمل + مصاريف عامة + نسبة ربح ← السعر المقترح، مع حفظ سجل كل الحسابات وإعادة استخدامها |
| **مؤشرات أسعار السوق** | أسعار الخشب والحديد والقماش وغيرها، مع نسبة التغيّر عن آخر سعر، وسحب السعر مباشرة إلى الحاسبة |
| **سجل الديون** | اسم الزبون، الهاتف، العنوان، البضاعة، المبلغ، دفعات جزئية، تنبيه المتأخر، اتصال وواتساب |
| **الطباعة** | فاتورة طلبية، كشف الطلبيات، سجل الديون، كشف دين مفرد، سجل التسعير — بتنسيق A4 عربي، مع خيار الحفظ كملف |
| **الإعدادات** | بيانات الورشة على المستندات، نوع الحساب (حرفي/تاجر) والحرفة، العملة، القيم الافتراضية، نسخ احتياطي |

---

## التقنيات

- **React 18 + TypeScript + Vite** — المسار الاقتصادي: قاعدة شيفرة واحدة للويب والموبايل.
- **PWA** — ملف `manifest.webmanifest` وعامل خدمة (`public/sw.js`) للعمل دون إنترنت والتثبيت
  على الشاشة الرئيسية.
- **Firebase** — المصادقة (Auth) وقاعدة البيانات (Firestore) مع تخزين محلي دائم للمزامنة بعد
  انقطاع الاتصال.
- **تنسيق RTL مكتوب يدوياً** — `src/styles/global.css` هو مصدر التصميم الأساسي، ويدعم
  الوضع الليلي تلقائياً.
- **Tailwind CSS 4** — مضاف كطبقة مساعدة فوق التنسيق اليدوي (بدون Preflight، انظر
  `src/styles/tailwind.css`)، وأدواته مربوطة برموز التصميم نفسها.

## التشغيل محلياً

```bash
npm install
npm run dev
```

يفتح التطبيق على `http://localhost:5173`. بدون إعدادات Firebase يعمل التطبيق في **الوضع
المحلي**: كل البيانات تُحفظ داخل المتصفّح، ويمكن تعبئة بيانات تجريبية بضغطة زر من الصفحة
الرئيسية أو من الإعدادات.

أوامر أخرى:

```bash
npm run build     # بناء نسخة الإنتاج في مجلد dist
npm run preview   # معاينة نسخة الإنتاج
npm run lint      # فحص الأنواع بـ TypeScript
```

## أدوات المساعد الذكي (MCP)

ملف `.mcp.json` في جذر المستودع يعرّف خادمَي MCP يستعملهما Claude Code لبناء الواجهات:

| الخادم | الغرض | يحتاج مفتاحاً |
|--------|-------|----------------|
| `21st` | توليد مكوّنات واجهة وبحث في كتالوج 21st.dev | نعم |
| `shadcn` | بحث وإضافة مكوّنات shadcn/ui من السجلّات | لا |

خادم `21st` يقرأ المفتاح من متغيّر البيئة `TWENTY_FIRST_API_KEY`، فلا يُكتب المفتاح داخل
المستودع أبداً. احصل على مفتاح من [21st.dev/mcp](https://21st.dev/mcp) ثم صدّره في صدفتك
قبل تشغيل Claude Code:

```bash
export TWENTY_FIRST_API_KEY="your-key"
```

### shadcn/ui

المشروع مهيّأ لاستقبال مكوّنات shadcn/ui، فتُضاف مباشرة:

```bash
npx shadcn@latest add button dialog
```

> **لا تشغّل `npx shadcn@latest init`.** الإعداد مضبوط يدوياً ليتعايش مع `global.css`،
> و`init` سيعيد كتابة ملف CSS ويفعّل Preflight التي عطّلناها عمداً (تفاصيل السبب في
> تعليقات `src/styles/tailwind.css`).

ما هو مهيّأ مسبقاً:

| العنصر | القيمة |
|--------|--------|
| `components.json` | نمط `new-york`، متغيّرات CSS، أيقونات `lucide` |
| اختصارات المسارات | `@/components`، `@/components/ui`، `@/lib/utils` |
| `cn()` | في `src/lib/utils.ts` (clsx + tailwind-merge) |
| رموز التصميم | `bg-primary` و`bg-card` و`border-border` وغيرها مربوطة بلوحة ألوان التطبيق |
| طبقة `reset` | أصغر جزء من Preflight تحتاجه مكوّنات shadcn، معزول تحت `global.css` |

رموز shadcn مشتقّة من متغيّرات `global.css` نفسها، لذا تتبع المكوّنات المضافة الوضع
الليلي واتجاه RTL تلقائياً دون ضبط إضافي.

## ربط Firebase

1. أنشئ مشروعاً على [console.firebase.google.com](https://console.firebase.google.com).
2. من **Project settings → Your apps** أضف تطبيق ويب واحصل على إعدادات SDK.
3. انسخ `.env.example` إلى `.env.local` واملأ القيم:

   ```bash
   cp .env.example .env.local
   ```

   ```env
   VITE_FIREBASE_API_KEY=...
   VITE_FIREBASE_AUTH_DOMAIN=....firebaseapp.com
   VITE_FIREBASE_PROJECT_ID=...
   VITE_FIREBASE_STORAGE_BUCKET=....appspot.com
   VITE_FIREBASE_MESSAGING_SENDER_ID=...
   VITE_FIREBASE_APP_ID=...
   ```

4. فعّل **Authentication → Sign-in method → Email/Password**.
5. أنشئ قاعدة **Firestore Database**، ثم انشر قواعد الأمان الموجودة في `firestore.rules`:

   ```bash
   npx firebase-tools deploy --only firestore:rules
   ```

بمجرّد وجود القيم في `.env.local` تظهر شاشة تسجيل الدخول وتبدأ المزامنة بين الأجهزة.

> ملف `.env.local` مستبعد من Git، فلا تُرفع مفاتيحك إلى المستودع.

### بنية البيانات في Firestore

```
users/{uid}                      ← وثيقة المستخدم، تحتوي حقل profile
users/{uid}/orders/{id}          ← الطلبيات
users/{uid}/appointments/{id}    ← المواعيد
users/{uid}/calculations/{id}    ← سجل حسابات التكلفة
users/{uid}/marketPrices/{id}    ← أسعار المواد
users/{uid}/debts/{id}           ← سجل الديون
```

قواعد الأمان تمنع أي مستخدم من قراءة أو كتابة بيانات مستخدم آخر.

## النشر

### Firebase Hosting — تلقائياً من GitHub (موصى به)

المستودع يحتوي على سير عمل جاهز في `.github/workflows/deploy-firebase.yml` يبني التطبيق
وينشره على Firebase Hosting مع كل دفعة إلى `main`، وينشر معه قواعد أمان Firestore.

**الإعداد لمرة واحدة.** أضف سرّين من **Settings → Secrets and variables → Actions →
New repository secret**:

| اسم السرّ | من أين تأتي قيمته |
| --- | --- |
| `FIREBASE_PROJECT_ID` | كونسول Firebase → Project settings → General → حقل **Project ID** |
| `FIREBASE_SERVICE_ACCOUNT` | كونسول Firebase → Project settings → **Service accounts** → **Generate new private key** → افتح الملف المنزَّل والصق محتواه كاملاً |

بعدها يعمل النشر تلقائياً عند أول دفعة إلى `main`، أو يدوياً من تبويب **Actions** عبر
**Run workflow**. الرابط الناتج شكله:

```
https://<project-id>.web.app
```

**مفاتيح التطبيق (اختيارية).** لتفعيل تسجيل الدخول والمزامنة بين الأجهزة أضف أيضاً أسرار
`VITE_FIREBASE_*` بنفس أسماء `.env.example`. بدونها يُنشر التطبيق ويعمل بالتخزين المحلي على
جهاز كل مستخدم.

> سير العمل يتوقّف برسالة واضحة إن كان أحد السرّين ناقصاً، بدل أن يفشل في منتصف النشر.
> ومفتاح حساب الخدمة يُكتب إلى ملف مؤقّت ولا يُطبع في السجلّات إطلاقاً.

### Firebase Hosting — يدوياً من جهازك

```bash
npm run build
npx firebase-tools login
npx firebase-tools use --add          # اختر مشروعك
npx firebase-tools deploy --only hosting
```

ملف `firebase.json` جاهز: ينشر مجلّد `dist`، ويوجّه كل المسارات إلى `index.html` (توجيه من
طرف العميل)، ويمنع تخزين `sw.js` مؤقتاً حتى تصل التحديثات للمستخدمين.

> انتبه إلى `--only hosting`. بدونها قد يدخل Firebase في مسار **App Hosting**، وهو منتج
> مختلف مخصّص للتطبيقات التي تُصيَّر على الخادم. هذا التطبيق موقع ثابت ولا يحتاجه.

### أي استضافة ثابتة أخرى

ارفع محتويات مجلد `dist` مع إعادة توجيه كل المسارات إلى `index.html`.

## التثبيت على الهاتف

بعد فتح الموقع على الهاتف:

- **أندرويد (Chrome)**: القائمة ← «تثبيت التطبيق»، أو زر التثبيت داخل صفحة الإعدادات.
- **آيفون (Safari)**: زر المشاركة ← «إضافة إلى الشاشة الرئيسية».

يعمل التطبيق بعدها كتطبيق مستقل بملء الشاشة، ويشتغل دون إنترنت.

للحصول على تطبيق متجر حقيقي لاحقاً يمكن تغليف نفس الشيفرة عبر
[Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) أو Capacitor دون إعادة كتابة
الواجهة.

## بنية المشروع

```
src/
  components/     مكوّنات الواجهة المشتركة (حقول، نوافذ، بطاقات، أيقونات، الهيكل العام)
  context/        حالة المصادقة والبيانات والتنبيهات
  data/           طبقة التخزين: Firestore أو التخزين المحلي خلف واجهة واحدة
  hooks/          خطّافات مساعدة (تثبيت PWA)
  lib/            الأنواع، الحسابات، التنسيق، الثوابت، إعداد Firebase
  pages/          الشاشات: لوحة اليوم، الطلبيات، المواعيد، الحاسبة، الأسعار، الديون، الطباعة، الإعدادات
  print/          توليد مستندات الطباعة بتنسيق A4
  styles/         tailwind.css (المدخل) + global.css (التنسيق العام: RTL + وضع ليلي)
public/           أيقونات التطبيق، ملف الـ manifest، عامل الخدمة
```

طبقة التخزين موحّدة خلف الواجهة `Store` في `src/data/store.ts`، لذا يعمل التطبيق بنفس
الشيفرة سواء كانت البيانات في Firestore أو في المتصفّح.
